# 项目整理与开发路线

日期：2026-10-26。依据 Astra 的自动闪避方案、Luna 的机制库收尾、当前源码、056 发布清单和已有实测记录。

## 统一目标

用户最新目标已更新为“闪避怪物和攻击怪物”，允许删除无用内容，不必持续沿用全部旧指令。碰撞安全优先，自动攻击也必须恢复为默认能力；不扩大机关、跑图等旁支。工作源码 058 正恢复默认自动攻击，尚未替换正在运行的 057。

自动闪避的输出应是可执行的短程动作与连续路线：能及时到达、途中不碰撞、到达后有退路。计算依赖实时布局、身体范围、运动惯性、输入延迟、危险生效时间，以及敌人对候选玩家动作的响应。

机制库服务于这个目标。继续堆积动画关键词不能代替预测接入；收齐全部怪物也不应成为开始验证闪避的前提。先用已有 Swarm、蜘蛛和弹幕样本建立小范围闭环。

## 当前开发版

默认入口为 `IsaacExternalAssist057.exe`（`0.5.7-dev-dodge`）。发布时 51 项源码及数据与冻结版本一致，关键模块及包内资源逐项校验、EXE smoke 和 73 项相关检查通过。GUI 默认纯移动闪避；旧 056 和原指针备份保留。后续实际用户诊断观察到 6 次掉血至零，来源未知；本批采样规划中位 24.29ms、p95 33.01ms，未通过无伤验收。058 工作源码正按新目标恢复默认自动攻击，并针对这批实际失败改进预测和连续伤前证据。

共享追击路线前缀与批量终点出口探测保留全部候选和危险检查。24 次合成搜索的完整动作、路径、风险与报告和优化前一致，搜索中位约 25.79→18.02ms，p95 约 30.16→20.43ms；仅代表该有限离线输入。固定 Swarm 受伤片段仍有接触诊断。

## 本轮整理决定

1. 保留读取器、运动模型、危险几何、搜索、瞄准和输入门禁。当前没有证据支持整体推倒重写。
2. Luna 负责将机制库的静态目录加载、索引和唯一变体匹配从运行时观测职责中提取到 `engine_attack_catalog.py`，保持现有输出语义与兼容性；完成后由统筹者复核。审计细节见 [机制库整理审计](机制库整理审计-20261026.md)。
3. 统筹者维护 README、架构、问题清单、测试边界、开发顺序和发布差异核对脚本。避免多人同时修改相同文件。
4. 保留定位受伤仍有用的原始日志、恢复备份、冻结源码和发布清单。删除已完成的一次性旧版本准备/发布脚本与废弃 Preview15 入口，避免旧工具继续充斥开发入口。
5. 本轮不搬动平铺的 Python 模块。现有导入、打包、冻结测试依赖这些位置，先分清职责，再按实际复用需求提取模块。
6. 修正过期事实，历史版本的实验结果仍保留。旧交接单中的暂停是当时状态；当前授权恢复的是项目整理与必要重构。游戏文件边界继续生效。

## 观测到预测的接口约定

现状：`AttackMechanismDetector` 产出观测事件、候选、动作关联与覆盖报告；`engine_world` 暴露它们，`combat_evidence` 记录增量。`engine_hazards` / `engine_warnings` 和行为配置仍负责生成可用于碰撞检查的危险。机制库尚未自动成为完整危险预测器。

后续接入复用 `planner.Body` 与 `engine_search.HazardAtlas`，按一种机制一个可验证适配的顺序推进。不要把整个覆盖报告送入每条候选路线的热路径。

每项预测应明确：

| 信息 | 要求 |
| --- | --- |
| 身份 | J460、精确 Type/Variant/SubType、实际 ChampionColor、阶段；回退匹配标依据 |
| 时间 | 采集帧、最早识别时刻、生效起止；原生帧、动画帧、规划 tick 与秒明确区分并显式转换 |
| 几何与运动 | 圆、线段、冲刺走廊、落点或其他范围；是否锁定、持续瞄准或随候选路线追击 |
| 伤害条件 | 高度、碰撞类别、友敌、本地归属、玩家能力；未确定的条件保留未知 |
| 证据与误差 | 直接观测、静态候选、时序共现、模型预测分别标记；保留原始记录位置与预测时长相关误差 |

未检测到攻击不能解释为确认无危险。观测属性不证明命中；同帧/一帧关联不证明因果；唯一 Type.Variant 回退不证明 SubType 行为相同。

## 接下来按收益排序

| 顺序 | 具体工作 | 交付与验收 |
| --- | --- | --- |
| 1 | 提炼人工起步、带怪、转弯、短暂停留四段行为 | 交接单指定的 12 条代表帧证据；阈值不明确则待校准，录制未来不作新策略闭环证明 |
| 2 | 拆项测量读取、机制观测、集怪、主搜索、记录与输入时间 | 有界冻结回放，列 p50/p95/最大值、帧龄和运行条件；先确认耗时来源再改调度 |
| 3 | 设计快速避碰与中期路线更新的分工 | 快速层使用最新状态复查动作；后台建议不能阻塞输入或跨房间沿用。p95 ≤20ms 为目标，尚未达成 |
| 4 | 改善路线承诺、持续带怪和提前转弯 | 保留完整碰撞检查、归属和时效门禁；离线误差与原生受伤分开验收 |
| 5 | 接入一种已观测机制的危险预测，再扩展蜘蛛、弹幕和冲锋 | 每类报告提前量、漏检、误报、轨迹误差与耗时，不以名册数量代替行为效果 |
| 6 | 扩展混合房、Boss、难度和联机 | 按版本、房型、敌人、角色和失败分类；已有单账号不足以完成官方联机验收 |

原生专项拟采用预先选定的 10 次 Swarm 尝试，要求全部无伤、原生开门、日志完整且恢复通过。此为后续阶段目标，当前没有执行；也不能在现行采集边界下直接运行会安装桥接 Mod 的旧入口。先解决符合边界的采集/测试条件，或由用户明确改变该边界。

## 删除与发布的判断

可删除内容必须能说明替代入口、引用情况与恢复来源。本轮不为目录整齐删除历史证据，也不把过期文档中的旧数字抹成新版本结果。

新版本发布需要源码、资源与新增目录数据一并冻结，核对包内依赖及哈希，再更新默认指针。已删除限定旧基线的 `scripts/publish-events045.py` 和 build 顶层的旧版本 prepare/publish 脚本；这些一次性脚本不能直接发布当前代码。首轮仅整理；后续本阶段已按此流程交付 057 开发版，清单明确标记原生闪避尚未验证。

`scripts/audit-project-state.py` 默认只读并打印 JSON，可用 `--output` 保存核对结果。返回成功只表示发布身份、EXE 与冻结源码一致；开发差异会列出，不表示新源码通过行为验收。
