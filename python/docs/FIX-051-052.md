# 051 / 052：围堵前抢出口，减少角落停留

当前程序为 052（0.5.2-external-core）。051 的固定房验证失败，后续由 052 接替；不把失败版写成已解决。

## 用户最新记录的原因

会话 20261025-173720-3a7d84，050。5 次血量变化分别在 frame 234/264/294/324/354，均关联到 281/0 Swarm 的唯一普通接触请求候选。角色从 frame 199 的约 (131,242) 退向 frame 216 的 (83,166)，随后滞留在左上角约 (70,150)，连续再次受伤。

对应决策的 early_retreat_cost 长时间恒为 18，safe_region_cost 恒为 32，出口诊断为 0。它们在此时已失去区分路线的能力。原有主要动作搜索只看 24 个规划 tick；退路图又把整条边在数个未来时刻一起检查，容易将“现在能抢先穿过、随后会封闭”的路线判成不可用。剩下的舒适距离排序会让短时远离怪物的墙角更有吸引力。

另一个漏项是 Swarm 的 target 指针为 0、动画为 Fly，未进入原先的普通 Walk/已知目标追击分支；模型会低估转向后继续追击的风险。原记录规划中位耗时约 66.68ms，27 次决策过期，进一步减少了实际执行突破的机会。上述是代码和日志证据，不证明每条未选路线在真实闭环中都一定成功。

原局退出码为 0，捕获结束握手未完成，不能称引擎崩溃。其后先归档当前文件、核验备份，再恢复 48 个路径；原始不完整标记保留。恢复账本 records/recovery/20261025-050-run1，原局摘要已补存。

## 051 的修改

- 新增 engine_egress：按角色的观测位移速度构造带时间的移动图，检查能否先于封闭穿过边，并要求到达后仍有出口。评分包含生存层数、尽快抵达可用空间及地形余量，避免全部退化为相同最差值。
- 新增 J460 / 281/0 / Fly 的版本与阶段追击配置。单人目标唯一时建立追击分支；未知联机目标仅预警，明确远端目标继续跟随远端；本地控制归属政策不变。
- 每次身体/弹幕几何碰撞仍优先规避，完整包络安全路线仍优先。只有包络重叠已不可避免时，在保留立即延迟保护之后，才将脱围进展放在额外未来包络暴露量之前。这是显式排序变化，所有原始危险和包络指标继续计算、记录。
- 保留不同首个移动方向的几何安全分支，减少突破路线在早期因舒适距离不佳而被剪掉。
- 所有追击体合并向量计算，保留逐体参考算法用于数值回归，不通过删怪或缩小碰撞半径提速。

新增固定原生房 tests/native-rooms/swarm-four-directions.xml。读取器核对原生 room variant 和最低敌人数，防止实际测成随机房。该原生加载房的实测 difficulty=0；XML 的 difficulty 属性不是 Hard 游戏难度，结果不作困难模式通关证据。怪物、伤害、武器及生命规则没有改。

## 051 失败与 052 修正

051 两局固定房都死亡，各 6 次受伤。规划中位耗时 134.46/139.74ms，43/41 次过期释放。首轮说明新目标图直接在输入线程构建不合适。

052 将未来图转到单个后台工作线程；计算未完成时使用明确标记的轻量地形建议，每轮即时碰撞检查仍在控制线程执行。旧房间后台结果不允许应用到新房间，建议过旧时降回待更新状态。

固定房还暴露冷启动位移单位迟迟没有拟合的问题：051 第 144/135 帧才观察到约两倍位移比例。原有拟合要求足够多相邻观测，在过期释放和跳帧下可能拖延；052 用小间隔、方向投影残差与多样本一致性先估计位移比例，再等待完整拟合，不把初估谎称为完整惯性拟合。原始用户局在较早时已经完成单位拟合，因此不能拿这个新发现替代该局的选路原因。
