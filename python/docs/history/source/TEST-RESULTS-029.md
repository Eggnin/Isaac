# 0.2.9 现场卡住回归（2026-10-23）

## 现场证据

本轮只读检查当前仍在运行的游戏，没有重启游戏、修改本局、发送真实测试按键或使用 Computer Use。原始现场快照保存于 `D:\IsaacAccessAssist\tests\stuck028-live.json`；最小可重放数据为 `fixtures/stuck-large-room-028.json`。

在这间 grid 28×9 / shape 7 的大房间里，玩家位于约 (321.54,243.99)，剩余两只敌人约在 (608.45,234.25) 和 (640,280)。日志连续多个决策都是 move=(0,0)、fire=null，当前位置及所选站位成本均为 0，但攻击拒绝原因含 wall。输入法当时已经关闭，角色 ControlsEnabled=true，操作冷却为 0。

问题包括三处：合法像素位置投影到粗网格时，最近节点 (330,250) 恰落在障碍膨胀区域；导航只取该节点，返回无穷大；站位成本忽略无穷大导航，并漏算地形挡枪成本。结果是被石头挡住的射线仍被当作零成本的理想站位。

## 改动

- 像素位置连接附近可达节点，连接段也检查完整玩家中心可行图。不会凭相邻节点位置安全就跨墙连接。
- 不可达导航有明确成本，高于当前场内有限导航成本，不再把缺失路线当作零成本奖励。
- 攻击站位成本加入与发射判断相符的地形射线检查；保留 Brimstone、Knife、Tech X 等现有 grid-pass 类型例外，未把身体遮挡规则强加给这些类型。
- 新增 firing_navigation_status / firing_navigation_start 日志。碰撞、缓冲、危险、退路等级保持原顺序，没有加入随机强制移动。

## 验证

修改前对现场快照做完整控制链的无输入重放：move=(0,0)、fire=null、start_goal_cost=0。

修改后同一快照选择 move=(1,0)，起点目标成本约 12.434，选中末端约 10.652；危险碰撞计数 0，完整选中路径的玩家中心均在可行区域内。此时仍暂不发射，因为初始射线尚被挡住；选择移动是为了到达有效射击位置。这是冻结场景的第一步决策验证，不是已经实机绕行清房。

集中运行：

```powershell
python -m unittest -q test_regressions_025 test_regressions_026 test_regressions_027 test_regressions_028 test_regressions_029 test_engine_app test_engine_weapons test_engine_world test_engine_warnings test_planner test_native_getters test_win_platform
```

**110 项通过，0 失败、0 错误，0.480 秒。** 新增五项覆盖：合法像素邻近阻塞网格、细墙不连通、非法坐标、挡枪成本及 grid-pass 例外、完整现场快照选择安全进展。测试中的输入均为模拟对象。

现场快照重放规划耗时冷启动约 55.95ms，后两次约 40.70/40.83ms；这些是本机离线重放耗时，不是游戏 FPS。新增连接段和地形射线检查带来计算成本，没有删减危险或降低检查分辨率来换速度。

## 安装与边界
