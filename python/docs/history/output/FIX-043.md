## 修改

1. 碰撞排序区分不含延迟膨胀的几何预测和延迟包络。旧代码将两者混成一个碰撞层，所有路线都触及缓冲时，可能为了减少缓冲重叠选到会撞本体的路线。现在先比较几何碰撞，再比较完整延迟包络，原缓冲值、实体、采样范围、过时输入门禁均保留。诊断新增geometry_hits、latency_envelope_hits，predicted_safe仍要求包络无碰撞，不能拿geometry_hits=0冒充完整安全。
2. Haunt追击体：本局原生记录为type260/variant10/FloatChase，共两个独立实体，目标引用为0，旧动画分支没有识别它们。单人唯一玩家或有明确目标引用时，加入追击分支；在搜索中根据每条候选的完整玩家路径重算追击，而非让它们继续追旧速度的虚拟玩家。保留实测直线/曲线分支。多人的目标引用不明时只加软候选，不断言追本地玩家、不回退到玩家0；已确认远端目标不改成本地追击。
3. 大蜘蛛和Migraine：本局受伤前快照已暴露target_position。扩展原普通蜘蛛的排队冲刺预约到type94，并给type869的Jump/Walk添加原生目标点和走廊预约，避免只按当前接近零的速度推断它们停住。不重新瞄准到猜测的玩家坐标。
4. 包围与无退路：附近存在多个独立威胁或追击体时，将首4帧控制段的退路质量提前到攻击和软舒适距离之前，而非只评估24帧终点。受压模式要求能证明退路；合法像素位置却无法连接退路图时不再得0惩罚，避免吸引角色进入无出口口袋。远离压力时保留原兼容行为，仍允许安全原地射击；不靠假定下一发会击杀来删除威胁。
5. 受伤账本和诊断新增几何风险与追击参数，使“已有危险却不退”和“未识别追击”可以分别检查。

## 验证与边界

78项相关离线检查通过：包括本局冻结快照、两个独立追击体、多人不明目标保持软分支、原生冲刺/落点、追击候选整段与分段的一致性、多个方向追击的静止/撤离路径对比、口袋退路惩罚、原有安全射击/狭窄路线和旧卡点回归。没有全量测试、视觉验证或Computer Use。

本局6次受伤各保留约提前1/6/12帧的18份快照。早期仅修改碰撞排序时，4165帧的静态回放从5个几何碰撞帧降到0；随后按用户补充加入真实追击分支，此“0”不再成立，最终模型仍预测风险（该帧12个几何碰撞帧）。因此不得将阶段性结果当最终无伤改善。最终Boss近身快照仍可能没有安全候选，必须靠更早的路线选择；尚未实机确认能否摆脱。

部分已贴身快照的预测碰撞帧也未下降；几何排序优先无碰撞，其后是更晚首次碰撞、较小重叠，并非单独最小化碰撞帧数。新增预约使原先漏掉的危险变为可见，不能直接跨模型把计数增减当受伤率。最终逐快照结果见combat043-candidate-final.json；旧模型结果见combat043-baseline-extended.json，二者假设不同。
