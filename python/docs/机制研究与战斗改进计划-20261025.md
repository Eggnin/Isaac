# 以撒机制研究与战斗改进计划

历史计划日期：2026-10-25。研究对象：J460 忏悔+、外部辅助、045 房间测试。下文保留当时研究依据与统计，不作为当前版本状态。2026-10-26 已统一到 [项目整理与开发路线](项目整理与开发路线-20261026.md)：默认发布 056，原生无伤验收失败；工作源码另有未发布机制库。此前 FIX-046～056 和原始验证继续保留。

## 1. 主要结论

战斗知识应落成五类可计算信息：敌人目前的阶段、接下来可能出现的攻击、危险区域何时生效、玩家还剩哪些可行退路、当前武器在哪些位置能够有效命中。每条规则同时保存适用版本、变体、依据和不确定性。

现有读取、世界建模、惯性拟合、束搜索、瞄准和日志已经具备基础。优先投入事件时序、危险模型和任务完成证据，再改进站位与攻击选择。普通房、Boss、多怪组合和机关房都纳入研究与覆盖账本，实施时按实际损失排序。

原版引擎没有在本次资料中提供一套可完整审查的全部 AI 源码。Lua API 文档说明字段和接口，房间编辑器代码说明配置格式，攻略提供行为线索；精确的 J460 出招时机、碰撞阈值和变体差异需要本机数据校准。REPENTOGON 扩展 API 与当前基础 Lua 能力分开登记，不能假定扩展已安装。

实战范围继续为躲避、攻击和必要按钮。玩家负责拾取、走门和探索；物品只研究其对当前移动、武器、射程、免疫和碰撞的影响。

## 3. 房间应该如何表示

### 3.1 配置与实时状态

房间配置包含类型、变体、子类型、形状、尺寸、难度、权重、门位置及格点上的加权生成项。进入后还会有精英替换、分裂、召唤、死亡生成和波次变化，所以规划必须以实时实体为准。配置适合建立覆盖账本与选择相关回归房间。[配置转换源码](https://raw.githubusercontent.com/Basement-Renovator/basement-renovator/main/src/roomconvert.py)

同时保存实际楼层/楼层类型、配置 StageID、房间身份、维度和测试 generation。StageID 表示房间设计来源，不能直接当第几层；跨房间复用坐标、房间格子编号或实体地址时，不能继承旧状态。房间维度下的唯一身份也不能仅依赖一个 GridIndex。[RoomConfigRoom](https://wofsauge.github.io/IsaacDocs/rep/RoomConfig_Room.html)、[RoomDescriptor](https://wofsauge.github.io/IsaacDocs/rep/RoomDescriptor.html)

### 3.2 三张地图与一个动态危险层

| 表示 | 内容 | 对战斗的作用 |
| --- | --- | --- |
| 玩家通行图 | 真实边界、门边、岩石、坑、角色半径、飞行与移动状态 | 判断能否到达、刹停和穿过窄口 |
| 武器通行图 | 普通泪弹、幽灵、穿透、激光等各自的阻挡规则 | 判断站在某处到底能否打中 |
| 退路拓扑 | 连通区域、狭窄出口、封闭口袋、转移路径 | 提前识别下一秒会被围住的位置 |
| 动态危险层 | 接触体、子弹、激光、落点、爆炸、危险地形及时间窗口 | 避免只看当前距离或终点安全 |

当前代码已有多张掩码和退路图。下一步重点检查非矩形/窄房间、动态格点和危险障碍的边界，而不是重新实现整套地图。

原生 CheckLine 明确区分地面通行、爆炸与弹道检查；地形可走和武器可穿过应保持独立。读取到的路径成本还可能是 NPC 导航偏好，不一定等于实体碰撞或实际伤害区域。[Room.CheckLine](https://wofsauge.github.io/IsaacDocs/rep/Room.html#checkline)、[PathFinder](https://wofsauge.github.io/IsaacDocs/rep/PathFinder.html)

### 3.3 机关与开门

普通必要压力按钮要全部处理完才可能完成房间；奖励、贪婪、铁路、事件和 Kill Plate 的效果不同。处理按钮时要保留危险规避，并按“接近 → 实际覆盖触发位置 → 等待效果 → 完成/失败”分阶段。导航耗时和踩后等待不能共用一个起始时刻。[按钮机制](https://bindingofisaacrebirth.wiki.gg/wiki/Reward_Plate)

本机 enums.lua 还提供 RoomDescriptor.FLAG_PRESSURE_PLATES_TRIGGERED，注释说明其表示所有必要压力按钮已触发，且没有按钮的房间不会自动设置该位。这是可评估的补充完成证据；当前读取器只取该描述器的清房位，尚未暴露这一按钮位。

测试继续以原生门打开为切房终点。日常辅助则在无战斗与必要机关时交还操作。

## 4. 怪物行为、玩家处理方式与代码规则

下表是从游戏行为和玩家经验归纳的策略设计，具体参数均待 J460 数据校准。一个实体可能同时属于多类。

| 行为类别 | 代表/识别线索 | 玩家常用处理 | 转成程序需要什么 |
| --- | --- | --- | --- |
| 地面持续追击 | Gaper、接近中的普通近战怪 | 保持有效射程，横移输出，避免最后才后退 | 接近时间、刹停距离、路径绕障与下一出口 |
| 飞行/高速多向追击 | Attack Fly、Lil' Haunt、Army Fly | 合流前换到开阔方向，集中处理一个威胁 | 多目标同时预测、持续可用出口、局部攻击收益 |
| 直线或连段冲刺 | Charger、Squirt、Dingle 等阶段 | 观察锁定后侧移，给后续冲刺留空间 | 蓄力、锁定、冲刺、恢复的阶段模型；冲刺走廊与重复次数 |
| 蜘蛛式停顿后突进 | Spider 系列 | 空闲时保留余量，避免进入即将到达的位置 | 已观察目标点、启动延迟、短程扫掠与落点预约 |
| 跳跃/跳落 | Hopper、Leaper、Ministro、Monstro、Widow | 提前离开落区，落地后再争取输出 | 腾空与落地危险分离、锁定时点、落地弹幕/小怪 |
| 定点瞄准射击 | Horf、Maw 等 | 等瞄准后小幅横移，保留可射击站位 | 射击方向、发射时间、子弹速度与最小可行横移 |
| 预判射击 | Lil' Haunt、部分投射怪 | 瞄准提交后改变移动方式 | 区分瞄当前位置和瞄未来位置；持续直跑并非统一解 |
| 扇形、十字、环形弹幕 | Clotty、各种 Boss | 选择足够宽的空隙，避免横穿密集区域 | 弹幕相位、空隙宽度、玩家半径与通过时间 |
| 跟踪、曲线、变速、反弹弹幕 | ProjectileFlags 指定 | 看转弯与回返，保持移动通道 | 用 flags 和阶段参数构造轨迹，保留观测拟合及误差 |
| 激光/扫射 | Vis、Gluttony、Bloat、The Haunt 等 | 蓄力阶段离开射线，按具体攻击选择侧面或转移 | 预警、激活、旋转、反弹、终止与玩家逃离时间 |
| 爆炸及击杀后危险 | 炸弹、爆炸怪、相应精英 | 留出爆炸距离后再击杀，防止死亡生成堵出口 | 引信、爆炸范围、击杀时刻与后续生成 |
| 召唤/复活/再生 | Hive、Nest、Cultist、Globin | 能安全接近时优先减小持续增援 | 已有战略优先级，再加入接近风险和有效击杀时间 |
| 护甲/方向性弱点/暂时不可伤 | Host、Knight、Mask+Heart 等 | 抓开口阶段或换到可伤方向 | 脆弱窗口、朝向、被保护关系；接触危险独立保留 |
| 固定机关/环境伤害 | 无敌炮台、刺、红便便、火、地面效果 | 使用掩体和安全走廊，先完成必要机关 | 危险区域独立于可走区域；免疫能力按种类应用 |
| 多阶段/死亡分裂 | Boss 阶段切换、Gaper 等生成 | 留心清空旧目标后的新威胁 | 生命周期追踪、父子/生成者关系、旧危险尾部保留 |

怪物目录说明接触、弹幕、召唤和地面效果是不同威胁；这里的分组属于为本项目设计的行为接口。[怪物目录](https://bindingofisaacrebirth.wiki.gg/wiki/Monsters)

### 4.1 对当前高风险情况的具体含义

- Lil' Haunt 的攻略描述包含模仿移动、追击和预判射击；主 Boss 还有不可受伤阶段及变体差异。当前 260/10 FloatChase 的逐点追击预测是一个模型假设，要与实际速度/目标点和出弹记录对照，不能把所有阶段归为同一种追击。[Lil' Haunt](https://bindingofisaacrebirth.wiki.gg/wiki/Lil%27_Haunt)、[The Haunt](https://bindingofisaacrebirth.wiki.gg/wiki/The_Haunt)
- Monstro 包含接近小跳、喷弹、离屏跳落与落地弹幕；因此仅扩大一个移动圆的半径不够，需要区分阶段和攻击窗口。[Monstro](https://bindingofisaacrebirth.wiki.gg/wiki/Monstro)
- 精英属性会改变速度、死亡效果和脆弱条件，Boss 变体也可能改变攻击组合。规则键至少包含 Type、Variant、SubType、精英信息与当前状态。[精英怪](https://bindingofisaacrebirth.wiki.gg/wiki/Champions)
- 玩家经验中同时存在绕行与小幅横移：对简单瞄准弹，短移可以保留输出线；对多方向逼近，需要更早转移。两种行为应由当前威胁和空间决定。[走位经验](https://www.reddit.com/r/bindingofisaac/comments/1b0ozwa/)

## 5. 躲避与攻击必须一起考虑的机制

### 5.1 命中盒、碰撞类别与时间

Entity.Size 表示命中盒尺寸，SizeMulti 调整横纵形状。当前世界模型取最大的缩放系数构成包围圆，具有保守性，也可能挤掉窄通道。先在真实碰撞证据上检查误差，再决定哪些类型需要更精细形状。接触伤害、是否阻挡泪弹、是否可被攻击和是否必需清理要分开表达。[Entity](https://wofsauge.github.io/IsaacDocs/rep/Entity.html)

伤害回调在应用前触发；TakeDamage 还存在下一帧应用的缓冲。碰撞时位置、回调序号、之后掉血位置和动画帧不能混为同一个瞬间。受伤后的击退也可能使后续快照远离真正接触点。[伤害回调](https://wofsauge.github.io/IsaacDocs/rep/enums/ModCallbacks.html#mc_entity_take_dmg)、[Entity.TakeDamage](https://wofsauge.github.io/IsaacDocs/rep/Entity.html#takedamage)

当前预测按每秒 30 步使用位置、速度与时窗；渲染回调次数和动画帧不能直接替代物理步数。蜘蛛网、滑动地面、减速、冻结、恐惧、受击等变化还会影响拟合与行为，需在状态变化时检查模型是否仍适用。已有读取和拟合继续保留，只补必要的状态和失效标记。

### 5.2 弹幕与激光

当前已读取 ProjectileFlags、Height、FallingSpeed、FallingAccel，并有观测加速度/转向、SMART 跟踪与部分特殊弹幕预测；这为扩展提供了基础。

仍需要显式补齐延时改变 flags/速度、反弹、绕行、回返、加减速等行为。在基础轨迹之外，高度与 ANY_HEIGHT_ENTITY_HIT 影响危险判定，不能统一把每颗子弹视作永久地面圆，也不能凭一个未经校准的高度阈值忽略它。[ProjectileFlags](https://wofsauge.github.io/IsaacDocs/rep/enums/ProjectileFlags.html)、[EntityProjectile](https://wofsauge.github.io/IsaacDocs/rep/EntityProjectile.html)

激光模型已有线段、样本点、旋转与圆环表示；改进重点是前摇到激活的时序、宽度和可脱离路径。动画事件可用于校准阶段，但需先取得具体动画定义中的事件名称。[Sprite.IsEventTriggered](https://wofsauge.github.io/IsaacDocs/rep/Sprite.html#iseventtriggered)

### 5.3 有效输出与下一次接触

攻击需要考虑实际发射点、玩家速度继承、射程、目标运动、地形与护甲阻挡、可伤窗口、蓄力/释放、武器冷却及随从发射位置。当前代码已支持这些内容中的多项，但“存在武器配置”不等于所有组合已经验证。

下一步用两条估计辅助选位：

- 危险到达时间：接触、子弹、激光或爆炸最早可能伤害玩家的时间，扣除决策/输入延迟和刹停需要。
- 有效击杀时间：下一次能发射、飞行与可伤阶段的等待、剩余有效命中次数及冷却；同时保留估计置信度。

当撤离窗口更紧时，提前换区并保留火力方向。只有可靠命中证据支持时，才把快速击杀当作减少未来威胁的收益；预测会击杀不能直接把敌人从硬碰撞模型删除。

攻击本身也会改变敌人运动：击退、减速、受击触发和死亡生成都可能让原轨迹失效。实际观察到的响应用于下一步重预测；尚未发生的预期击退不能作为安全保证。entities2 配置中的 collisionMass 也是核对这类差异的入口。[entities2.xml](https://wofsauge.github.io/IsaacDocs/rep/xml/entities2.html)

受伤冷却期间的恢复策略单独评估，正常目标仍为避免第一次受伤，不把短暂无敌视为常规通行许可。

## 7. 新日志对计划顺序的影响

固定样本：用户会话 20261025-140624-cb74b6 的前 3 个已结束 045 局，后续及活动局不计入。详见 [逐条时序证据](../records/research/20261025/045-first3-event-timing.json)。

1. 三局均死亡结束并恢复，采集完整性通过；共 seen=written 3,039,468 次回调。
2. 19 次受伤中，原关联结果为 12 个唯一候选、7 个未匹配。只读复核找到 19 个按玩家/房间/楼层对应的唯一时间候选：10 个同帧、9 个前一帧。
3. 7 个未匹配的回调都恰好落在 previous_frame，下界使用严格大于而将其排除。这与伤害缓冲机制相符。修复时应建立时序对齐和每个 callback_seq 的唯一归属，避免简单扩大窗口产生重复/多源误配；不能把回调请求直接写成最终应用因果已经完全确定。
4. 源引用包括：子弹 6、Attack Fly 4、Gaper 2、Crazy Long Legs 2、Spider 1、Ring of Flies 1、炸弹 1、Type 0 环境请求 2。两条 Type 0 请求 flags 均为 DAMAGE_POOP；炸弹请求含 DAMAGE_EXPLOSION。子弹还能沿记录的 SpawnerEntity 分到 Horf、Maw、Host、Crazy Long Legs 等。由此可以把接触、远程、爆炸和环境危险分开排序。
5. 三局有效游戏速度约 0.959、0.836、0.874；规划中位约 30.1～34.2 ms。完整记录有实际性能代价，但这三局不是受控性能对照，不能把全部下降都归因于某个采集函数。

因此实施前两步应同时重视“关联准确”和“完整记录下的时延”，再依据源类别修躲避。原始流继续逐条保留。

## 8. 建议的目标结构

保留读取 → 建模 → 任务 → 规划 → 输入的主链路，增加共享的行为描述和事件时序契约。

| 组件/接口 | 建议内容 |
| --- | --- |
| EventTimeline | 引擎帧、实体帧、动画帧、callback_seq、观测时间、阶段/房间/玩家身份、请求与 HP 应用关联 |
| BehaviorProfile | Type/Variant/SubType/精英/版本、阶段条件、目标锁定、轨迹族、可伤窗口、死亡后行为、依据与样本量 |
| RoomTopology | 玩家通行、武器通行、危险格点、连通区与出口；以原生实际几何校核 |
| ThreatEnvelope | 已观测碰撞体与预测分支、起止时间、硬/软含义、误差上界、目标归属 |
| CombatObjective | 目标/射击位置集合、攻击意图、禁止区域、等待条件、阶段专属进展、完成/失败证据 |
| AttackOutcome | 没出弹、出弹未命中、受阻、目标不可伤、命中请求、实际 HP 变化，允许保留未解释状态 |

这些是后续改造接口，本轮尚未新增生产模块。优先增量接入已有模块，避免并行维护多套瞄准或危险定义。

### 验证方法

仅运行与改动有关的冻结快照和短时序检查；对追击敌人额外使用带候选玩家路线的半闭环回放，注明敌人响应简化。采用用户启动的有界实测核对最终行为。整个方案遵守不做全量/无关测试、不做视觉验证、不用 Computer Use、不由我自行启动游戏的约束。

分层统计采用实际来源与暴露量：每 1,000 战斗帧受伤数、接触/弹幕/环境/爆炸分组、有效伤害与出弹比例、危险下零移动时长、方向翻转率、到射击位距离变化、算法 p50/p95/p99、过期释放次数、日志写入量。未完成 Boss、空房和不同版本分别计数。

### 从参考仓库借鉴的部分

AIsaac 的公开实验记录显示，模型可能在简化模拟器中获得看似良好的结果，却因原生阶段遗漏而迁移失败；攻击课程和原生引擎留出评估有参考价值。当前项目优先采用这些验证思路，保留已有可解释规划器。其 Linux AB+ 实现、Windows J460 桥接与本项目版本相关字段分别核对。[AIsaac README](https://github.com/Lceoliu/AIsaac)、[战斗实验分析](https://raw.githubusercontent.com/Lceoliu/AIsaac/main/docs/COMBAT_RL_EXPERT_REVIEW.md)
