# 机制库目录与观测边界整理审计

日期：2026-10-26

## 改动范围

将静态名册、J460 事件候选、动画目录、逐怪物机制候选及身份解析移到 `src/engine_attack_catalog.py` 的 `AttackCatalog`。`AttackMechanismDetector` 继续负责快照观测、运行时累计状态和覆盖报告，通过目录对象取得静态数据。

原先，检测器分别为事件候选、动画目录、机制目录建立三份 `Type.Variant` 回退字典。本次只保留一份基于静态 EntityConfig 身份构建的唯一变体索引；解析目标目录时仍要求对应 EntityConfig key 确实存在。这样保留原匹配规则，同时去掉重复字典及其重复遍历。

未改 `observe()` 的机制判断与累计逻辑，也未改输出字段。Wiki 名册仍从 `engine_monster_catalog.tsv` 单独加载；静态索引仍只接受标记为 J460 的来源。扩展候选词表、历史报告、游戏和 Mod 均未改。

## 身份匹配核对

- 完全相同的 `Type.Variant.SubType` 返回 `exact_identity`。
- 静态 EntityConfig 中某个 `Type.Variant` 只有一个 SubType，且所查静态目录含该配置时，才返回 `unique_type_variant_entity_config`。
- 多 SubType、目录中缺少唯一配置、格式不完整或找不到的身份不回退。
- 唯一变体索引来自静态机制目录的 EntityConfig key；ChampionColor 与 `is_boss` 仍构成独立运行时 profile，不会因共用基础动画目录而合并其运行时观测档案。

## 证据分层核对

- `observed_property`、`observed_entity`、`observed_relation` 是进入 `_seen_mechanisms` 和确认机制覆盖的直接证据。
- `animation_heuristic`、`static_candidate`、`timer_candidate`、`observed_transition` 与 `unclassified` 不会因此成为确认机制。
- 静态事件帧候选仍记录匹配帧和身份匹配依据；它不证明 AI 执行了攻击、生成攻击对象或造成伤害。
- 动作—攻击对象关联只由已确认攻击对象、可追溯的 NPC 来源及同一观测帧中的来源动作生成，置信标签仍为 `same_snapshot_source_action_object_cooccurrence`；它是时序共现，不是因果结论。
- `unknown_effect_emission` 即使读到了 Effect 实体，也保留 `unclassified` 置信级别，不计入确认机制。
