# 架构与文件归属

更新：2026-10-26。项目入口见 [README](../README.md)，当前取舍和开发顺序见 [项目整理与开发路线](项目整理与开发路线-20261026.md)。保留现有 Python 模块接口，按实际职责整理。

主链路：只读快照 → 世界与运动模型 → 战斗或房间机关任务 → 路径搜索与瞄准 → 归属、时效检查 → 输入。

记录链路：快照与决策 → 受伤/攻击/阻塞证据；临时 Lua 观察器 → 原始回调流与伤害索引 → 血量变化关联。

## 生产模块

以下 Python 文件均在 src。

| 层 | 模块 | 责任 |
| --- | --- | --- |
| 感知 | engine_reader、native_getters | 只读快照、版本校验、本地角色及引擎字段 |
| 建模 | engine_world、engine_motion、engine_behaviors、engine_hazards、engine_warnings、engine_targeting | 实体、地形、运动与危险预测；版本/变体/阶段限定的行为配置 |
| 机制观测 | engine_attack_mechanisms | 直接观测、静态候选、动作时序关联与覆盖；候选不直接提升为危险预测或因果证据 |
| 静态目录 | engine_attack_catalog | 加载 Wiki 名册及三类 J460 静态目录，共享唯一 Type.Variant 索引；精确身份优先、歧义不回退 |
| 任务 | room_mechanism | 战斗/普通按钮任务、完成证据；hard_run_route、first_floor_goal 保留历史模式 |
| 规划 | planner、engine_search、engine_retreat、engine_egress、engine_kiting、firing_navigation | 动作碰撞、退路、按到达时间展开的脱围建议、带怪路线、可达射击位 |
| 攻击 | engine_aim、shot_geometry、engine_weapons、engine_grid_attack | 共用射线几何、武器控制、受限清障 |
| 控制与界面 | engine_app、win_platform、input_ime | 调度、窗口输入、归属/时效门禁、GUI |
| 会话 | native_session、game_launch、hard_run_start、fixture_observer | 启动、就绪与独立测试入口 |
| 记录 | engine_diagnostics、combat_evidence、run_journal、loop_history、engine_event_journal | 原始证据、受伤时序、跨局汇总、回调关联 |
| 房间测试 | realtime_room_test、room_test_runner、room_test_transport | 实时测试、认证切房、结束握手 |

算法模块不负责启动游戏、传送房间或磁盘清理。完整统一任务仲裁接口仍是待评估改造，当前没有宣称已经实现。

## 测试桥接

runtime/bridge/room_test_bridge.lua 在临时测试模组内处理连接、状态与切房；engine_event_capture.lua 枚举可用回调，每条写入，观察器返回 nil。日常 GUI 不自动安装桥接。

当前机制采集边界禁止改动游戏安装、选项、存档、Mod 和 Steam 设置。旧 `room-test` 入口会复制临时 Mod 并改写 EnableMods，因此本轮不运行；不把临时采集桥接带入线上联机。进程外 `engine_reader` 使用 ReadProcessMemory，与游戏内 Lua 桥接是两条不同的观测路径。

Python 读取小型伤害索引，将伤害请求与血量/冷却变化关联，不逐帧解析整个大流。完整性错误或低空间停止循环并保留数据。

## 发布与开发

- 默认入口选择 057 开发版（0.5.7-dev-dodge），51 项当前源码和数据已冻结，73 项定向检查与打包 smoke 通过。日常 GUI 只控制移动，不安装机关路由、不自动开局、不做射击导航。旧战斗路径保留用于对照及已有专项，非日常默认。
- 057 的原生闪避与端到端延迟尚未验收。056 固定 Swarm 房的 5 伤清房、6 伤死亡及约 121/109ms 规划中位是历史基线，不能当作 057 的实测结果。用 scripts/audit-project-state.py 核对文件身份与开发差异。
- dist/*.BUILD.json 保存程序、源码、资源、脚本哈希及工作源码差异。
- runtime/room-test-runtime045 继续作为后续版本共用的固定测试资源，目录后缀不表示默认程序版本。修改桥接后须更新发布资源并核对清单。
- 当前启动脚本从 dist/Latest-Isaac-Program.json 选择程序，日志写入 records。
- tests 存放冻结快照和定向检查。scripts/check-related.py 不进行全量测试发现。
- scripts/replay-combat-sequence.py 顺序回放限定 1～300 帧；只生成诊断，不启动游戏或发送输入。模型假设与真实受伤/回调因果分开报告。
- 052 的未来脱围建议由单个后台线程构建，仅处理不可变危险快照与地形副本；当前动作的全量碰撞检查仍在控制线程。房间切换使旧建议失效，未完成或过旧时提供明确标记的地形建议。
- scripts/Run-Native-Session.ps1 的可选 RoomFixture 加载 tests/native-rooms 下的原生 XML；就绪时验证配置身份、敌人数和本地角色。固定房难度按原生读数报告，不将 XML difficulty 属性当成游戏 Hard 模式。
- archive 用于旧实现和兼容入口，不作为当前发布来源。

## 机制库的数据与预测边界

本机 J460 静态资源 → 653 项 NPC 目录及静态参考 → 事件、动画、机制候选目录 → 运行时观测和历史审计。Wiki 469 项名册与 184 项补充 NPC 分开统计。

`engine_world.observe_attack_mechanisms` 将观测结果交给调度与记录层；`combat_evidence` 写新增签名。现有危险体仍由世界建模、SpecialHazards、Warnings 与行为配置构建，`planner.Body` 和 `HazardAtlas` 负责规划时的危险几何。机制观测报告尚未转换为完整的未来攻击预测。

静态目录生成脚本在 scripts；可再生成的运行数据放 src，以便以后随程序打包；输入清单、历史审计、阶段快照放 records/research。J374 外部参考只作历史研究，本机 J460 为当前静态基线。详细步骤见 [机制库说明](攻击机制检测库-20261026.md)。

## 目录用途

| 目录 | 用途与整理规则 |
| --- | --- |
| src / tests / scripts | 当前开发、冻结用例与工具；定向检查从 tests 运行，不全量发现 |
| runtime / native | 测试资源与原生工具；存在不代表当前允许加载或注入 |
| dist / build/releases | 已发布程序、清单和冻结源码；不与 src 混为一谈 |
| records | 原始证据、研究派生索引、恢复账本与验证；不删除原始日志 |
| archive / docs/history / scripts/history | 历史实现和资料；保留兼容引用，不作为新开发入口 |
| tools / build/vendor | 本地依赖与外部参考，不能把外部项目能力视为本项目能力 |

## 迁移与空间

旧 C 盘 external 指向 src；旧 handoff 的 outputs、work 以及 D:\IsaacAccessAssist 通过目录联接访问新位置。outputs/loop-runs 再指向 records/loop-runs。兼容入口不占第二份数据。

D:\IsaacAssistIO 指向整个项目，为游戏 Lua 提供 ASCII 文件路径。scripts/Room-Test-Paths.ps1 在游戏启动前检查联接归属和路径存在性；已有同名普通目录或指向其他位置时明确报错，不覆盖。JSON 中保留 capture_canonical_directory；实际采集文件仍落在原逐局目录。自动生成的逐局子目录使用 ASCII 名称。

旧目录中混放的 Terraria 内容未迁入。Steam、游戏安装和实际存档继续使用原有位置。

构建缓存可以重建；已发布固定源码、版本清单、恢复备份、受伤及卡点证据保留。NTFS 透明压缩不改变日志内容和访问路径。
