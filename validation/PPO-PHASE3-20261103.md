# Phase 3 · PPO 微调（2026-11-03）

目标：**不重新初始化 Actor**，从 Phase 2 的 BC 权重继续 PPO，用真实战斗结果做奖励，并给出可复现的对照。

本轮把 PPO 链路完整跑通，但结论是负面的：12,288 帧的 PPO 没有在验证集上超过 BC，更没有接近 MPC。按用户规则不替换任何策略，也不接实机。

## 2. 奖励设计（全部来自真实转移）

`ShapedEnvironment` 用引擎返回的真实 `info.enemyDamage`（实际敌人 HP 下降）、`info.healthUnitLost`（实际掉血）、终止状态和帧数计算奖励，不使用 MPC 自己的评分：

| 分量 | 权重 | 依据 |
| --- | ---: | --- |
| 实际造成伤害 | +1.0 / HP | `info.enemyDamage` |
| 实际受到伤害 | −8.0 / 半心 | `info.healthUnitLost` |
| 清房 | +40 | `terminal.cleared` |
| 死亡 | −40 | `terminal.dead` |
| 时间 | −0.002 / 帧 | `info.framesAdvanced` |
| 长时间无输出 | −0.02 / 帧（连续 120 帧无伤害后） | 真实 `enemyDamage == 0` 的累计 |
| 无意义空动作 | −0.01 / 决策（move=none 且 fire=none，非终止） | 抑制"站着不动" |

反逃跑与反无脑输出的约束都在这里：无输出惩罚只针对"打不到敌人"，清房有正向奖励，死亡惩罚高于同样时长的生存收益；没有把存活时间当目标。

## 3. 训练配置与过程

- 初始化：BC balanced（`f5fd702c…`），学习率 `1e-4`、γ `0.995`、GAE λ `0.95`、clip `0.2`、entropy `0.002`、value coef `0.5`、4 epochs、minibatch 256、rollout 1024。
- 环境：`scene=auto`（12 个 Boss 房轮换）、训练种子 `3JY1 6FLR`、action repeat 1、单回合上限 1800 帧。
- 规模：12 次迭代 × 1024 = **12,288 帧**，15 个回合，**0 清房 / 14 死亡**，合计输出 1326 HP、掉血 90 半心。
- 熵始终在 **2.06–2.39**（两个头最大熵约 3.8）；critic 解释方差 **−0.089–0.025**，即价值函数基本没有学到回报结构；value loss 0.93–12.1。
- 训练期平均回合奖励 −4.03，最好的一次 100.9（第 11 次迭代，单回合幸运值，不能当作策略改进）。
- 断点续训已验证：从 `latest-training.json` 恢复后继续第 13 次迭代，计数、优化器与 checkpoint 连续。

## 4. 验证集对照（种子 7W3L，4 场景 × 900 帧，与 BC/MPC 同条件）

| 策略 | 死亡 | 掉血 | 输出 | DPS |
| --- | ---: | ---: | ---: | ---: |
| BC balanced（PPO 起点） | **1/4** | **13** | 308.5 | 2.92 |
| PPO best（训练回合奖励最高） | 2/4 | 21 | 332 | 3.35 |
| PPO latest（第 12 次迭代） | 3/4 | 23 | 307 | 2.92 |
| MPC 专家 | **0/4** | **7** | 656 | 5.47 |

结论：

- PPO **机械链路是通的**：初始化、奖励、GAE、clip、checkpoint、续训、评估都能跑；但没有产生可用改进。
- best/latest 都表现为"输出略增、生存变差"（332 vs 308，但掉血 21 vs 13、死亡 2 vs 1），与 Phase 2 的 stride3 同一个失败模式：在弱模仿策略上做策略梯度，首先被放大的是射击频率，而不是躲避能力。
- 12k 帧、15 个回合对 PPO 远远不够；critic 解释方差接近 0 说明优势估计基本是噪声，更新方向不可信。这个规模下**不应**继续加迭代来"等它变好"。
- 评估纪律：只在验证集上选择模型。PPO 两个候选都输给 BC，因此 held-out 测试集没有再对 PPO 做探索性评估（避免污染测试集）。

## 6. 下一步

PPO 的瓶颈不在算法实现，而在教师与状态表示：

1. **先修 BC 的移动模仿**：拼接上一帧动作/2–3 帧观察历史的输入特征（只改输入维度），或在 BC 阶段加入 MPC `sequence` 首段作为辅助监督。当前 move 准确率 ~0.40 是上限瓶颈。
2. **PPO 前先预热 Critic**：用专家数据做价值回归（`updateSupervised(valueCoefficient>0, valueTarget=回报)`），或先跑纯专家数据的 critic 训练，避免解释方差为 0 时继续更新策略。
3. **加 KL 锚定**：PPO 更新时对 BC 策略加 KL 惩罚/早停，防止"输出略增、生存变差"的漂移；同时把评估门槛固定为"验证集死亡 ≤ BC 且掉血 ≤ BC"。
4. 达标后再扩大 PPO 数据量（≥100k 帧）与场景/种子数；仍不达标就不替换 MPC。
