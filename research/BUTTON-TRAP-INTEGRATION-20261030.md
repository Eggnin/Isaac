# 银按钮、击杀按钮与653项身份归类

正式 C++ 主程序已加入两种按钮对策，产物为 `bin/IsaacGamebot.exe`。汇总与分类一致性检查见 [验证结果](../validation/buttons-traps-20261030.json)。

银按钮是网格 `20.0`。Planner 逐块导航，只有原生 `state=3` 才计为已按下；全部按钮按下后继续等待房间 `FLAG_PRESSURE_PLATES_TRIGGERED`，不以停留帧数或普通敌人死亡代替完成。未完成前保留伸缩地刺等危险格的记忆，解除后清除此记忆并使用当前地形。解除只抑制已登记的联动陷阱源；其他敌人、已有弹幕、激光和爆炸仍参与躲避。

红色击杀按钮是网格 `20.9`。未按下时优先导航，途中按当前危险选择路线，暂停自动射击；按下后读取原生清敌、清弹结果。贪婪按钮 `20.2` 继续使用独立规则。

原版验证发现普通爆破苍蝇 `25.0.0` 在红按钮触发后仍会爆炸。因此保留其短时爆炸危险区和实际爆炸观测，不把红按钮理解为“按下即绝对安全”。嚎哭怪 `16.0.0` 的死后生怪与红色爆破苍蝇 `25.1.0` 的死后泪弹在本场景均未出现。

## 两种按钮的代表场景

测试使用原版离线引擎，以及独立进程中的正式 C++ Reader/Planner。Reader 通过只读进程内存读取 Wasm 中的原版地址空间；策略只提交普通移动、射击输入。

| 按钮 | 场景 | 结果 |
| --- | --- | --- |
| 银按钮 | 种子 `3JY1 6FLR`，`stage 10`，`d.315` | 第552帧四块按钮均为 `state=3`，解除标志置位；继续观察30帧后已清房 |
| 红按钮 | 同种子，隔离实例 `s.boss.1010` 中放置 `20.9`、嚎哭怪、两种爆破苍蝇及已有敌弹 | 第28帧由策略按下；敌人和已有敌弹清除，之后30帧未出现死后小怪或泪弹；真实爆炸继续进入威胁模型 |

银按钮证据：[原始报告中的 silver 用例](../validation/buttons-silver-red-20261030/report.json)。红按钮证据：[完成的原版用例](../validation/buttons-red-native-final-20261030/report.json)。初次红按钮布置命令发生在待切换房间加载之前，未形成有效场景；后续改用隔离实例的房间加载回调布置，失败记录保留。

两项使用 `debug 3` 保护角色，仅证明按钮识别、导航与机制闭环，不作为无伤成绩。按要求只采用两种按钮的代表场景，没有逐一测试23类陷阱。正式程序没有增加 Lua 或研究环境依赖。

## 653项的口径

653 是本机 J460 `EntityConfig` 中精确 Type/Variant/Subtype 组合数，包含普通怪物、Boss、部件及环境机关。总数保持653，其中25项已改为 `category=trap / role=trap_mechanism`，原分类保留。

| 分类 | 数量 |
| --- | ---: |
| monster | 322 |
| boss | 132 |
| unlisted_npc | 174 |
| trap | 25 |

用户列出的23类陷阱及其表示见 [陷阱目录](../data/npc/TRAP-ROOM-CATALOG.md)，完整653项见 [身份目录](../data/npc/ENTITY-CATALOG.md)。`203.0.0 Brimstone Head` 已明确标为陷阱。地刺、伸缩地刺、红大便等网格以及 Type 4 的两种 Troll Bomb 单独登记，不混入NPC计数。石眼 `201.0.0` 另有既存 `d.118` 银按钮联动证据，作为补充机关标记。

标记同步到 TSV、机制数据库、状态语义库和主程序运行时语义库。目录归类不表示25项都已取得攻击时点或无伤战斗验证。

构建命令 `powershell -NoProfile -ExecutionPolicy Bypass -File cpp/build.ps1 -Test` 完成，**123项通过、0项失败**。新增检查覆盖银按钮实际状态及完成标志、红按钮优先级和按下后的残留危险；分类检查确认各库保持相同653项与25项陷阱标记。

机制资料：[按钮说明](https://isaac.huijiwiki.com/wiki/%E6%8C%89%E9%92%AE)。正式运行仍通过 `Start-Assist.cmd`，自动控制默认关闭。
